### V2 浏览器手动验收顺序

1. 登录普通用户，展开用户名菜单；修改昵称后刷新确认保存，登录名与本人 Idea 保持；普通账号没有管理入口，直接访问后台/API 被拒绝。
2. 登录管理员，从下拉菜单进入独立管理区；目录按用途/名称选型，核对参数类型、默认值、必填提示和元数据版本。
3. 在工作台配置 Props、双向状态、Events、Slots、注册回调及资源，实际操作预览，保存模板并重载；未知属性、错误作用域、必填缺失、危险 URL/CSS/SVG 明确报错。
4. 新建独立页面目标，保存未发布时普通用户不能读取；发布后以普通用户访问 `/pages/:pageKey`，刷新仍显示。
5. 编辑页面草稿，普通用户刷新仍看到上次发布版本；再发布后才看到新内容。旧 revision 保存/发布返回冲突，不能静默覆盖。
6. 为一个已注册且未占用的既有区域保存/发布，回到对应业务页面确认挂载；首页录入不重复，原输入提示、提交、归档、卡片与详情继续使用。
7. 验证至少真实 DOM/指令目标、服务及清理、带作用域的槽、异步成功/失败回调；组件卸载后不遗留遮罩、消息或旧账号异步结果。
8. 令当前会话过期或禁用测试普通账号，确认提示登录、草稿保留；重新登录和切换账号后，旧响应不会覆盖新状态。数据库失败时明确报错，不显示保存成功。

## 2026-10-14 收尾复核

验收代理独立读取补充代码并检查控制流，而非仅依据新测试通过判断：

- 组件定义的 SQL 列、JSON 元数据和代码安装定义必须在标识、库和版本上保持一致，错配仍整体拒绝。
- 服务端意外错误的诊断日志仅记录注册路由模板、允许的方法、技术错误代码白名单及固定类型；不读取动态 URL/query、请求正文、SQL/params 或 error message/stack/name。
- 前端请求绑定会话代次；旧 401 不退出新账号或同账号重新登录的新会话。初始化和周期检查的旧 200/401/503 也不能覆盖新会话；当前会话 401 仍提示登录并保留草稿。
- Cookie 清理不受前端响应代次控制；当时将旧过期响应携带 Set-Cookie 的边界交给后端代理核实，2026-10-15 的修复与真实 HTTP 结果见上方。

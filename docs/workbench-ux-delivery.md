# Idea Purify 工作台 UX 改造与验收

更新：2026-10-16（Asia/Shanghai）。分支：`codex/workbench-ux`，工作区：`idea-purify-phase-a`。未合并 main、未部署；原主目录两份 pnpm 文件改动保持。基线为 `3284d40`。

## 旧版与新版流程

旧版：独立组件目录 → 选择并跳转工作台 → 认识节点/状态结构 → 添加、配置 → 手动“校验并预览” → 下滚找已保存方案/页面下拉 → 保存方案 → 配页面位置 → 保存页面草稿 → 发布 → 打开页面。新建、切换和重载可直接覆盖未保存编辑；成功消息不会随新修改消失。

新版：空白或“从简单表单开始” → 工作台内搜索并添加组件 → 直接编辑常用属性（复杂配置仍可展开完整 API） → 有效修改自动预览 → 显式保存草稿 → “选择发布位置”展开并滚到发布面板 → 保存页面草稿 → 发布 → 打开已发布页面。方案管理按名称、北京时间、保存修订和发布状态继续编辑。修改、保存、失败、未发布和已发布分别表达；未保存切换可取消或明确放弃。

| 用户任务              | 修改前                                                           | 修改后                                                    | 减少的负担与实际证据                                                            |
| --------------------- | ---------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 从目录选组件          | 在目录与工作台间跳转                                             | 当前工作台打开目录、搜索、直接添加                        | 浏览器实际搜索“输入框”得到4项，并添加到当前方案；没有路由跳转                   |

## 三种草稿的保存范围

| 类型                 | 保存位置与反馈                              | 恢复与边界                                                                   |
| -------------------- | ------------------------------------------- | ---------------------------------------------------------------------------- |
| 首页 Idea 未提交草稿 | 当前标签sessionStorage，明确“未提交”        | 刷新恢复；失效清缓存但当前内存可供同账号重登；退出清理；存储失败不冒充已保存 |
| 已保存组件方案       | 原MySQL方案API，显式保存                    | 方案管理继续编辑；方案保存不会自动改页面草稿或发布快照                       |
| 页面草稿 / 发布版本  | 原MySQL页面API，显式保存/发布，revision保护 | 普通用户仅读冻结发布内容；草稿修改不改变发布版本                             |

工作台未保存编辑的会话恢复仅在当前标签的内存中，不能承诺刷新或关闭后的自动恢复。刷新/关闭会提示，用户应先显式保存。未引入服务器自动保存；因此不存在隐含的自动保存成功状态。

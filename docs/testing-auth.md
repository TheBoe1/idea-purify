# 用户、权限与想法验收

本矩阵记录需要验证的结果。只有获得真实执行结果后，才能把相应项目记为通过。邮件发送 stub 仅证明程序调用了邮件接口，不证明用户收到邮件。

## 已确认的产品边界

- 密码使用带盐密码哈希；想法正文正常保存，并在界面作为文本显示。
- 未登录及会话过期时显示 Element Plus 登录/注册界面和提示；会话过期保留未提交草稿，已有账号重新登录。
- 管理员可以管理、禁用账号，但不能读取其他用户的想法。
- 原有无归属的 6 条想法保留在数据库，不出现在任何用户列表中。
- 邮箱可选；密码找回通过邮件重设新密码，不能还原旧密码。

## API 与数据权限

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 匿名访问 | 请求想法列表、详情和创建接口 | 返回 401，不能读写想法 |
| 无效或过期会话 | 使用不存在、被撤销、超过期限的凭据 | 返回 401，不能读写想法 |
| 自注册权限提升 | 注册或更新时提交 `role: admin`、其他 `userId` | 不获得管理员权限；身份以服务端会话为准 |
| 用户隔离 | A 创建想法，B 请求列表及 A 的详情 ID | B 列表无 A 数据；详情不返回 A 的内容 |
| 创建归属 | B 创建时伪造 A 的用户 ID | 记录属于 B；A 无法读取 |
| 管理员隐私边界 | 管理员请求普通用户的想法详情、列表 | 只能读取管理员自己的想法 |
| 管理权限 | 普通用户请求用户管理或禁用接口 | 返回 403，用户状态不变 |
| 禁用账号 | 管理员禁用 A，再以 A 的原会话及密码访问 | 会话不可用，不能重新登录；想法保留 |
| 历史无主记录 | 任意账号查询列表及旧记录 ID | 无主记录不公开，不自动归属首次注册账号 |
| 退出登录 | 退出后复用原凭据 | 原会话失效 |
| 数据库故障 | 无法查询/写入数据库后请求接口 | 返回明确失败；不返回成功或数据库凭据、SQL |

## 输入、请求与存储

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 非法账号/密码 | 缺字段、错误类型、过短、超长、不符合账号规则 | 返回 4xx，不创建账号或会话 |
| 未创建账号 | 使用不存在的账号登录 | 登录失败，不能自动创建账号；界面提供注册入口 |
| JSON 与请求大小 | 非 JSON、错误 Content-Type、大请求体 | 返回 400/415/413 等受控状态 |
| SQL 注入 | 正文包含引号、问号和 SQL 语句；账号含注入样式 | 正文作为字面量保存；账号校验；无越权、表损坏 |
| XSS | 正文保存 `<img src=x onerror=...>`、`<script>...</script>` | 列表、归档、详情显示文本，无脚本执行或新 HTML 节点 |
| 开发端口登录 | 从 5173、5174 或 localhost 登录，也允许无 Origin 的 API 客户端 | 正确凭据可登录；错误凭据仍返回 401，不提示来源不受信任 |
| 浏览器跨站写请求 | 跨站表单、文本提交或跨站 JSON 预检 | 非 JSON 返回 415；后端不开放 CORS 预检；Cookie 为 SameSite=Strict；不再按 Origin 白名单拒绝 API 客户端 |
| 密码哈希 | 检查两账号相同密码的存储值 | 不存明文；带独立盐；不是普通 SHA-256 直接散列 |
| 会话存储 | 检查服务端会话凭据字段 | 数据库不保存可直接复用的原始会话凭据 |
| Cookie | 检查登录响应 Cookie | HttpOnly、合适的 SameSite 和 Path；生产 HTTPS 时 Secure |
| 限流 | 高频重复登录、注册、找回密码 | 受控返回 429；不能绕过限制获取会话 |
| 错误信息 | 触发 SQL、邮件及哈希错误 | 不泄露密码、凭据、内部 SQL、邮件服务账号 |

## 密码重设与邮件

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 邮箱可选 | 不填邮箱注册、登录、创建想法 | 均可使用，界面说明无法通过邮件找回 |
| 找回响应 | 使用存在、不存在、无邮箱账号请求找回 | 不泄露账号存在性；不给出旧密码 |
| 重设链接 | 使用有效的一次性链接提交新密码 | 新密码可登录，旧密码失效，旧会话被撤销 |
| 链接滥用 | 错误、过期、已使用的重设凭据 | 拒绝且密码不变 |
| 邮件故障 | SMTP 不可达或认证失败 | 按实现合同返回受控结果；不能宣称已实际发送成功 |
| 真实邮件 | 配置选定提供者后请求邮件，并打开收到的链接 | 验证收件箱实际收到及完整重设流程；单元 stub 不替代此项 |

## 浏览器手动与多模态冒烟

1. 匿名进入首页、归档和想法页，验证鉴权提示和登录/注册界面。
2. 注册不带邮箱的普通用户 A；输入想法触发预设建议，提交成功后查看归档。
3. 点击归档记录进入详情，检查内容；打开与首页、归档同级的想法页，检查 Element 卡片列表及链接。
4. 刷新页面及重启后端，确认 A 的内容保留且重新读取正确。
5. 在未提交草稿时使会话过期，检查提示及登录界面，重新登录后草稿仍在，可继续提交。
6. 注册/登录用户 B，确认看不到 A 的记录；直接打开 A 的详情地址同样不可见。
7. 验证管理员能管理和禁用用户，但不能访问用户想法。
8. 检查时间倒序；无时间的记录在末尾并按正文编码序排列；相同内容以稳定 ID 决定顺序。
9. 保存 XSS 样式正文，检查页面仍为文本；失败时输入保留、按钮恢复可用。
10. SMTP 可用后测试真实找回邮件；检查一次使用后链接失效及旧会话不可用。

浏览器验收需要实际点击、输入、跳转、刷新，并保留最终截图。自动 HTTP 测试与 DOM 检查无法替代可视化检查。

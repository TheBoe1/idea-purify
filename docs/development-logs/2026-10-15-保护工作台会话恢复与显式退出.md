## 目标与验收要求

解决当前会话 401 后 App 卸载工作台导致的编辑丢失。提供按账号、当前标签内存的恢复基础；显式退出必须先保护未保存编辑，取消不退出；退出网络失败不得清内容；成功退出必须清理卸载时新产生的恢复缓存。

## 设计决定与依据

- 新增通用内存 Map，按非空 ownerId 隔离快照；取回为单次消费，避免重复恢复旧内容。调用方传入已复制的快照与编辑器初始化捕获的账号，不写入任何磁盘或服务端存储。
- 离开 guard 按账号注册，返回注销函数；注销时比较函数身份，旧组件卸载不能移除新组件的 guard。
- AppMenu 先确认再请求真实 logout API；等待确认期间身份变化，以 session generation 阻止旧会话的退出操作。
- 只有 logout 请求成功才清 Idea 和工作台恢复缓存；工作台清理在 Vue nextTick 之后执行，覆盖卸载期间的快照回写。
- 沿用 Vue 官方 watch/lifecycle 用法与项目 Element Plus 确认交互，不新增依赖、不修改 auth.ts、App.vue 或接口。
- Context7 不可调用；Vue 资料来源：[Watchers](https://vuejs.org/guide/essentials/watchers.html)。

## 旧流程与新流程

| 用户任务 | 旧流程 | 新流程 | 减少的负担 |
| --- | --- | --- | --- |
| 未保存时点退出 | 直接退出，编辑器卸载丢输入 | 先确认；取消保留编辑；允许且真实退出成功才清缓存 | 避免误退出后的重复搭建 |
| 确认退出但网络失败 | 原退出无工作台保护 | 保留登录、Idea及工作台内容，允许再次退出 | 不需要重建失败前的内容 |
| 401后同账号重登 | 工作台内存随组件卸载消失 | 父页卸载快照由按账号内存基础暂存，再由同账号领取 | 不需要重新输入中断前的V2配置（父页集成需另验收） |

## 未完成事项与下一步

- 父页现已注册仅确认的 `mayReplace`（只读核对），实际路由离开才提交丢弃标志；logout失败后保留后续恢复能力。
- V1子编辑器的实际编辑字段位于子组件，父页通用快照不包含其字段，需单独对接恢复或明确未完成。
- 内存恢复不支持浏览器刷新、标签关闭、进程退出；这些操作使用离开前保护，不能声称跨会话保存。
- 当前 Map API 为应用内部接口，按账号分键；它不构成针对同源恶意脚本的数据安全边界。

## 目标与验收要求

首页 Idea 未提交内容在本标签刷新、站内离开后可恢复；与工作台页面草稿、已保存组件方案区分。账号隔离，提交失败保留，迟到响应不清除后续修改；本标签存储失败有反馈，不能声称已保存到服务器。

## 设计决定与依据

- 使用 sessionStorage，按账号保存，仅用于未提交 Idea，不改 Idea API 和工作台草稿契约。
- 会话失效清理本标签持久缓存，仅保留当前内存以兼容已有同账号重登恢复行为；显式退出同时清理内存。不同账号不会看见前一账号内容。
- 存储成功状态使用“本标签暂存”，与“想法已提交至归档”区分；存储失败保留输入，提供重试，并在关闭/刷新前触发浏览器离开保护。
- 不更改 auth.ts；现有 AppMenu 明确退出已经调用 clearIdeaDraft。
- Context7 本会话不可调用；使用 [Vue Watchers 官方文档](https://vuejs.org/guide/essentials/watchers.html)核对同步 watch；使用 [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)核对刷新保留、按标签会话、关闭标签结束及 SecurityError 边界。MDN 也提示 opener 创建的新标签可能初始复制缓存，因此不把标签隔离描述成数据加密或绝对隐私保障。

### 旧流程与新流程

| 用户任务 | 旧流程 | 新流程 | 减少的负担 |
| --- | --- | --- | --- |
| 刷新后继续未提交想法 | 输入 → 刷新 → 原文丢失 → 重新输入 | 输入 → 本标签暂存 → 刷新并确认同账号 → 自动恢复 | 避免重新输入和记忆草稿 |
| 判断是否已经提交 | 只有提交请求结果 | 输入后明确“未提交/本标签暂存”，提交后保留原“想法已保存”归档入口 | 避免将本机缓存误当服务端提交 |
| 本机缓存不可用 | 没有缓存也没有状态 | 保留当前输入 → 显示失败 → 重试；离开前浏览器保护 | 可以恢复，而不是静默丢失 |
| 放弃未提交内容 | 手动删除文本 | 丢弃 Idea 草稿 → 确认；取消保留，确认期间新修改也不被清空 | 减少重复删除并防误操作 |

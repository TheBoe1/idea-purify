## 1. 用户目标与基线旧流程

目标用户熟悉 Vue，想把一个标题、输入框和提交按钮组合成可复用表单，并能修改验证规则、恢复编辑及明确发布。用户需要的是减少查找、来回跳转、手动预览和重复配置，而不是增加底层能力数量。

源码显示旧流程为：

1. 从账号菜单进入管理区，再从管理导航进入组件目录或方案工作台。
2. 在 `/admin/catalog` 按用途/名称筛选，点击“选择并配置”，跳转 `/admin/workbench?apiKey=…`；工作台首次挂载时添加一个节点。
3. 在“Schema 工作台”输入方案名称；在“根节点”下拉中查 API 并添加节点；分别展开 Props、Slots、Events、Callbacks 等配置。绑定自动建立的状态已存在，但表单组合、校验规则仍要理解属性/插槽层级。
4. 修改属性后点击“校验并预览”。继续修改后，预览仍是上一次有效快照，需再次点击。
5. 点击“保存方案”；要上真实页面，还需下滚到“页面绑定与发布”，输入另一套配置名称和发布目标，再“保存页面草稿”。
6. 点击“发布已保存版本”，再点击“打开已发布页面”。
7. 下次进入，需记住先在顶部“已保存方案”或下方“已有页面配置”选择内容，二者不是统一方案列表。

已存在且应复用的基础：目录已有用途筛选；`makeApiNode` 已创建 required props、modelValue 状态和常见文本插槽；MySQL 保存带时间、revision；更新/发布有 `expectedRevision`；草稿与发布快照隔离；V2 业务表单预览只模拟提交，私人 Idea 数据预览只用模拟值。问题集中在操作组织和状态真实性。

## 3. 实时预览的安全边界

`WorkbenchRenderer.vue:36–56` 的 deep watch 会重建 runtime、清理旧实例。`runtime.ts:396–420,704–719` 已把私人 Idea 查询和业务录入分成 preview/published；应保留。`runtime.ts:622–634,725–735` 的挂载服务会调用真实 Element Message、Notification、MessageBox 或 Loading；自动刷新预览若照常反复触发，会打断编辑。应让预览挂载服务保持显式触发或模拟，保留发布态正常行为及手动测试入口。

自动预览还需：无效输入不闪退、不误说已应用；防抖期间状态明确；前一 runtime 的异步任务只更新自身，清理定时器/浮层；不能让预览调用 Idea 写 API、真实上传、外部请求或影响当前页面路由。仍保留显式“重新预览/重置预览”供复杂数据和运行态重置使用。

## 4. 最小可行改造与审查边界

1. **先修 P0**：编辑快照/保存状态、离开保护、重名和长度反馈、局部布局保护、失败恢复。保留 `expectedRevision` 和后端冻结发布；手动保存足够，当前迭代无需为自动保存引入队列/新的存储接口。
2. **局部重组工作台**：顶部方案名称、准确保存/发布状态、保存/发布入口；可打开的方案管理面板；工作台内组件搜索/常用添加；编辑和持续预览同页。保留现有 Node/TypedValue 编辑器和注册表，复杂 API 放到仍可直接展开的高级区域。
3. **完成 A–H 浏览器验收后评价效率**：用明确任务核对操作数与完成率，记录真实耗时；没有独立测试者时只能称维护者任务验证，不能声称 3–5 名用户研究已完成。

建议新流程：进入方案工作台 → 新建空白/简单表单 → 搜索并添加组件 → 修改常用属性并立即看到有效预览 → 保存可复用方案 → 选择发布位置并保存页面草稿 → 发布已确认版本 → 查看真实页面。已有用户可跳过模板，直接进入完整编辑。
